Cross-site scripting (XSS) from unencoded output

Visitor text written straight into HTML can run scripts in other users' browsers. Fix: encode every output with Server.HTMLEncode.

At a glance: the code

✘ BROKEN code
q = Request.QueryString("q")
%>
<input name="q" value="<%= q %>">
<p>You searched for: <%= q %></p>
<script>var lastSearch = '<%= q %>';</script>
<script> in the link runs in the victim's browser.
✔ FIXED code
Function H(v)
    H = Server.HTMLEncode(v & "")   ' Null-safe
End Function

q = Left(Request.QueryString("q") & "", 200)
%>
<input name="q" value="<%= H(q) %>">
<p>You searched for: <%= H(q) %></p>
<a href="fixed.asp?q=<%= U(q) %>">Link</a>
<script>var lastSearch = '<%= JS(q) %>';</script>
The same text is shown harmlessly, character for character.

1. The symptom

A search page or comment shows a pop-up, a strange login box or a redirect. Security scanners or a client's audit report flag "Reflected/Stored XSS". Sometimes it just shows up as broken layout when someone types < or a quote.

2. Why it happens

<%= Request("q") %> writes whatever the visitor sent as HTML. If that text contains <script> or breaks out of an attribute with a quote, the browser runs it as part of your site, with access to the user's cookies and the page. Stored XSS (saved in the database and shown to others) is the most dangerous kind.

3. How to spot it

  • <%= Request(...) %> or Response.Write of database or form values without encoding.
  • Values placed inside value="...", href or inline <script> blocks.
  • Test with <b>x</b>: if the x is bold, output is not encoded.

4. The fix

Encode at output time, for the place the value lands: Server.HTMLEncode for HTML text and double-quoted attributes, Server.URLEncode inside URLs, and a JavaScript-string escaper for values inside <script>. Wrap them in tiny helpers (H(), U(), JS()) so it is easy to use them everywhere. & "" avoids the error Server.HTMLEncode(Null) raises for empty database fields.

5. Checklist

  • Every dynamic value in HTML goes through H() / Server.HTMLEncode.
  • Attributes always use double quotes (HTMLEncode does not encode single quotes).
  • URL parts use Server.URLEncode; script values use a JS escaper.
  • Database values are encoded too (stored XSS), not only Request values.
  • Cookies that hold logins are set with Secure on HTTPS sites.
